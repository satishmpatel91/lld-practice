Step 5 · the bug that appeared three times

Ceiling a division

Both fee calculators round part-periods up. Each one got that wrong first, in a different way — and the daily one got it wrong in a line that visibly contains Math.ceil. Drag the stay and compare.

2h 00mparked

Hourly · 20 per hour

Daily · 300 per day

The third form is the nastiest: without the (double) cast the division is integer division, so it truncates before Math.ceil ever runs. The hourly calculator only escapes it because 60.0 is a double literal. In any ceiling of a division, check that the division itself is floating point.

Step 7 · the lesson worth keeping

What the boolean means

compareAndSet answers “did I win”, not “was it already that value”. Getting that backwards in free() did more damage than a crash.

first attempt
if (occupied.compareAndSet(true, false)) { throw new IllegalStateException( "Parking spot is already free"); } // throws on every SUCCESSFUL release, // and stays silent when it really was free
fixed
if (!occupied.compareAndSet(true, false)) { throw new IllegalStateException( "Parking spot is already free"); } // losing a race for a spot is normal, so // tryOccupy returns boolean; freeing an // unheld spot is broken, so free() throws
In unpark the spot was released and the exception propagated, so ticketRepository.remove never ran. Spot free, ticket still valid, driver handed a stack trace instead of a receipt — and presenting the same ticket again issued a second receipt for a car that had already left. 15 of 51 tests caught it.

Two more fixes followed from the same change. Lombok's class-level @Getter had generated getOccupied() returning the AtomicBoolean itself, so any caller could release any spot — a field's type changed and the public API silently widened to match. And claimFreeSpot had been claiming inside a stream filter, which is correct only because sequential streams are lazy. A side effect inside a predicate is a predicate that lies.
